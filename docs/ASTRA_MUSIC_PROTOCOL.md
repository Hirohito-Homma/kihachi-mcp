# Astra music protocol

Astra は作曲だけを担当します。Ableton Live への接続、保存、書き出しは持ちません。

```
制作指示 → MusicPlan → 検証 → 既存の LiveMutationPlan → 人の承認 → 既存の実行
```

`MusicPlan` の schema は `kihachi.music_plan.v1` です。テンポ、キー、拍子、小節、トラック、ノートだけを持ち、Live の命令は持ちません。

最初の対象は Slap Bass の 8 小節です。D# minor、110 BPM、4/4。Kick、ドラム、パーカッションは残す指定で、計画に含めません。音域は MIDI 28–64、推奨は 32–52 です。スラップなどの番号は楽器のラベルであり、Live デバイスの操作にはまだ使いません。

小節から拍への変換は `musical_time.bar_start_beats` です。1 小節目は拍 0、4/4 の 17 小節目は拍 64 です。

変換先の命令は、実行側が既に持っているものだけです。

| MusicPlan | LiveMutationPlan |
| --- | --- |
| トラック | `create_midi_track` |
| シーン | `create_scene` |
| クリップ | `create_session_clip` |
| ノート | `replace_clip_notes` |

テンポは計画に記録しますが、明示しない限り Set のテンポは変えません。トラック位置は Live を読む前は仮の値です。再生状態は `UNKNOWN`、保存はしません、実行もしません。承認は既存の `ApprovalGate` が計画のハッシュに結び、ノートを変えると承認は無効になります。

Studio の「計画を確認」は、選んだ役割をオフラインで組んで結果だけを表示します。役割が全パートのときは、パートごとにトラックを分けます。「この計画を承認」は既存の承認記録にその計画のハッシュを残します。「承認しない」はトークンを作りません。Astra へは送らず、Live にも送りません。

「読み戻しを確認」は、承認済みの計画だけを Studio の中の偽の Set で実行して読み戻します。Live を読む前の計画は偽の Set に合わせ直すので、ハッシュが変わり、もう一度承認が要ります。偽の Set が計画どおり応答しても、実機の結果でも音の完成でもありません。

「実機の Live に送る」は、1 回目で実機の Set を読み、トラックとシーンを末尾に置き直します。トラック名は `KIHACHI Bass 1a2b3c4d [KIHACHI]` の形で、計画ごとに 8 桁が付きます。ハッシュが変わるので、もう一度承認したあとの 2 回目で 1 回だけ送り、読み戻します。再生中・録音中、読んだあとに Set が変わったとき、同じ名前のトラックがあるときは送りません。保存はしません。
